# 出文章流水线：取文字 → 翻译 → 按作者角色成文

本文件是 `fetch_for_article.py` 之后的工作方法。目标：用最小成本拿到可靠文字，并把它梳理成**结构匹配作者身份、读者能直接读**的中文文章。暂不涉及剪映/剪辑。

## 目录
1. 决策链为什么这样排 & manifest 怎么读
2. 三种文字来源的可信度与清洗
3. 非中文默认翻译成中文
4. 按作者角色/视频类型选文章结构（核心）
5. 成文通用规范
6. 视频默认不 OCR 的边界

## 1. 决策链为什么这样排 & manifest 怎么读

成本与可靠度从低到高：**字幕 < 音频转写 < 视频 OCR**，所以默认严格按此顺序，能省则省。

- `route=subtitle`：已得到 `*.srt` + `*.clean.txt`（清洗稿）。**直接拿 clean.txt 成文，不再转写、不下载媒体。**
- `route=audio`：得到最小音频，`need_transcribe=true`，先用 transcribe.py 转写再成文。
- `route=video-for-ocr`：只有画面、没有可用字幕/音轨时才到这；默认停在“已下视频”，不自动 OCR。

`fetch-manifest-<id>.json` 字段：`route`、`artifacts`(产物绝对路径)、`subtitle`(选中的语言/手动或自动)、`need_transcribe`、`need_translate`、`next_steps`。每次先读它确认走了哪条路、产物在哪。`--force subtitle|audio|video` 可强制路线（例如用户明确要音频、或怀疑自动字幕质量差想改走转写）。

## 2. 三种文字来源的可信度与清洗

- **手动字幕最可靠**（作者/社区校对过）；**自动字幕**是语音识别结果，可能有同音错字、漏标点。clean_subtitle.py 已自动：去序号/时间轴/`<c>`标签/HTML 实体、合并被切碎的断句、消除 YouTube/B站自动字幕“滚动累积”的重复（相邻 cue 前缀叠加只留增量）。
- 清洗后仍需快速通读校一遍：专有名词、数字、同音字（常见错字表见 transcribe-and-translate.md）；**只改错、不替作者加料**，听不到/字幕缺的内容标“（不确定）”，不要编造。
- 音频转写稿同理；字数与时长要相称（中文口播约 250–320 字/分钟，明显偏少说明 VAD 截断或音频损坏，需重转）。

## 3. 非中文默认翻译成中文

字幕语言或转写文本非中文时，**默认译为中文**（用户明确要保留原文/双语才例外）。

- 达意优先、不逐词硬译：按中文表达重组语序，符合中文同类作者讲同类话题的口吻（如英文技术口播译成中文技术博主的自然说法，不要翻译腔）。
- 专有名词/产品名/缩写首次出现用“中文（English 原词）”，之后用通行中文简称；单位、数字、版本号保留并换算到读者熟悉的口径。
- 口播里的填充词（you know / like / I mean）省略；但作者的观点、限定条件、因果不能丢。
- 需要双语对照时，逐段“原文—译文”并排，规范见 transcribe-and-translate.md。

## 4. 按作者角色/视频类型选文章结构（核心）

先判断**作者是谁、对谁讲、想达成什么**，再套对应结构；不要把所有视频都写成同一种流水账。

| 作者/视频类型 | 典型信号 | 推荐文章结构 |
| --- | --- | ---|
| 教学/教程/演示 | “教你/怎么实现/step by step/上手” | 一句话这是什么、能解决什么 → 前置概念 → 分步操作（带顺序）→ 关键参数与坑 → 小结/适用条件 |
| 新闻评论/深度调查/科普叙事 | 讲事件、机制、来龙去脉、多方关系 | 抓人的由头/场景开场 → 核心机制讲清（怎么运作）→ 来龙去脉/时间线 → 影响与各方博弈 → 结论与启发 |
| 测评/产品/模型体验、基准解读 | 跑分、实测、对比、demo | 结论先行（值不值得关注）→ 规格/基准 → 分项实测（按 demo 分段）→ 优缺点 → 适合谁/怎么选 |
| 经验分享/观点/行业洞察 | “我的经验/我认为/踩坑/方法论” | 核心观点 → 支撑论据与真实案例 → 可复用的方法/清单 → 行动建议 |
| 访谈/对话/播客 | 两人以上、问答 | 主题背景 → 按议题（不是按时间）归纳各方观点，标清是谁说的 → 分歧与共识 → 关键 takeaway |
| 发布/宣传/带货 | 官方发布、卖点密集 | 是什么 → 新特性/卖点 → 演示验证 → 与上代/竞品差异 → 适用人群；**主动去营销腔、保留客观判断** |
| Vlog/纪录/直播切片 | 生活、过程、随拍 | 按主题或时间线归纳，砍掉无信息片段，突出主线与关键事件，不逐句复述 |

判断不了类型时，默认用“结论/是什么 → 主体分点（带小标题）→ 小结”，并在交付时说明你的归类依据。

## 5. 成文通用规范

- 读者往往**不了解背景**：开头用一句话讲清“这是什么/为什么值得看”，可用读者熟悉的事物做认知锚点（例如知道豆包，就用“相当于国外版的豆包…”类比），但不歪曲。
- 去口水词、重复和无意义寒暄，但**保留作者个人风格与关键原话**；分小标题、控制段落长度，方便扫读。
- 事实、数字、时间、人名/机构名必须可追溯到字幕/转写稿，不脑补；来源是“作者称/视频显示”还是可核实事实要分清。
- 用户要“给朋友看/分享”时用口语、去 AI 腔；要正式博文就用书面结构。风格跟随用户与场景，不固定一种。
- 需要时间导览时，按视频自带分段或转写时间戳做“时间点 + 一句话内容”的精简目录，每条说清讲什么即可，不展开。

## 6. 视频默认不 OCR 的边界

- `route=video-for-ocr` 只代表“文字在画面里、且没有更省的来源”，脚本**下载后不会自动 OCR**。
- 只有当关键信息确实只存在于画面（代码、PPT、图表、屏幕操作、硬字幕烧录在画面）且用户需要时，再抽帧用 OCR/work-doc-extract 类能力识别，并与音频转写（若有）互补。
- 若该视频其实有声音（绝大多数），优先 `--force audio` 走转写，成本远低于逐帧 OCR；OCR 仅补画面里“说都没说”的信息。
