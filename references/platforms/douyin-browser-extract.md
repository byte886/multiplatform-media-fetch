# 抖音无登录浏览器直读提取法（脚本被风控时的兜底路径）

## 什么时候用

脚本下载链路被抖音风控拒绝时——特征报错：`Fresh cookies (not necessarily logged in) are needed` / HTTP 403 / web detail JSON 空 / 解析结果为空。

**关键认知**：报错里的 "not necessarily logged in" 说明抖音要的是**新鲜设备票据（ttwid）**，不是登录态。匿名 ttwid 会随时间失效，`--browser chrome` 复用登录态**不保证带新鲜票据**——2026-10-05 实测：匿名 ttwid 与 `--browser chrome` **均被拒**（同样的 Fresh cookies 报错）。此时不再折腾脚本，**直接走浏览器直读页面**：公开视频页面免登录可读，官方"章节要点"面板等效字幕，配合关键帧 OCR 可拿到完整文稿。

## 流程

### 步骤 1：浏览器打开视频页

用浏览器自动化（macOS 用 `browser-use-automation-mac` 技能 / `mac_computer_use_tool` plane=bu；其它平台对应浏览器技能）导航到视频页，任一入口均可：

- 抖音短链：`https://v.douyin.com/xxxx/`（会自动跳转）
- 分享链接：`https://www.iesdouyin.com/share/video/<纯数字ID>/`
- 直链：`https://www.douyin.com/video/<纯数字ID>`

### 步骤 2：读页面文字，优先取"章节要点"

打开后先做**非破坏性读**（`bu.get_page_text()` / `content_export()` / `snapshot()`），确认页面可读、未被登录墙拦截。页面右侧通常有抖音官方 **"章节要点"** 面板——平台自动生成的 AI 摘要，**等效字幕**，含时间轴分段（如 `00:00 引言 | 00:32 短剧制作过程 | 01:56 画布式创作 | 02:09 结语`）。

- 章节要点足够回答用户问题时 → 直接用作文稿骨架，跳到步骤 4。
- 需要画面细节（工具名、界面参数、按钮文字等）→ 继续步骤 3。

### 步骤 3：沿时间轴跳转 + 关键帧截图 OCR

按章节要点的时间点逐段定位：

1. 点击章节时间点（或拖动进度条）跳到目标位置，等画面稳定。
2. 截图关键帧（viewport 截图即可）。
3. 用 `Read` 工具直接视觉读取截图（多模态对小字识别优于 OCR 引擎）；或跑本地 OCR 兜底。
4. 对每个章节要点时间点重复，收集关键帧文字。

### 步骤 4：合成文稿

章节要点（骨架）+ 关键帧 OCR 文本（细节）→ 按用户需要组织成结构化解读（工具是什么/讲了什么/结论），并标注来源分层：页面直读文字（已查证）、画面 OCR（已查证）、博主口播结论（一方说法，页面文字没有时标注"未经核实"）。

## 登录墙判定

- 判定依据是**内容可达性**，不是页面有无登录按钮：读操作返回了目标内容（章节要点/标题/正文）就是可读，继续干活，不理会被动登录按钮。
- 读操作返回空/登录提示/截断预览 → 判定为登录墙，**下一条动作必须是 `interaction.request_action`（type=browserControl）** 把浏览器交给用户登录，不得换 URL、换平台、换搜索绕过。
- 抖音公开视频通常免登录可读；私密/关注可见/会员内容才需要登录（脚本链路同样拿不到，见 platform-strategy.md）。

## 注意事项

- 不尝试与风控对抗（换 UA、改 cookie、重试脚本）；浏览器直读是已实测的通路。
- 截图 OCR 只补"语音/文字面板没覆盖"的画面信息；章节要点已覆盖的口播内容不要重复 OCR。
- 时间轴跳转后必须重新截图（坐标/画面已变），不复用跳转前的截图。
- 与 `video-screen-ocr.md` 的分工：那篇处理**已下载的本地视频文件**的批量抽帧 OCR；本篇处理**浏览器页面实时画面**，用于"视频下不下来"的场景。
- 该浏览器是独立/后台实例，用户桌面可能看不到窗口，属正常；涉及登录移交时用户接管的是这个浏览器。
